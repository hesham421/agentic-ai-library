# Skill: gov-enforce-backend-contract

## Description
**GOVERNANCE ENFORCER.** Analyzes aias backend code and rejects ANY violation of the layer
contract. This skill is the architectural gatekeeper — it does NOT generate code, it VALIDATES
and BLOCKS non-compliant code. The project's facts it enforces come from the aias profile as
published in `governance/shared/` (see `CLAUDE.md` → "Project Facts"); the module's delivered
package, API document and db-script supply the per-module names.

## When to Use
- After ANY backend code generation (entity, domain class, repository, DTO, port, adapter,
  service, controller)
- As a mandatory post-generation validation step of every unit
- When reviewing a pull request touching a backend module
- When anyone claims a unit is "complete"

## When NOT to Use
- During code generation — this skill validates only
- For the §12 guardrails and module boundaries alone — use
  [`gov-enforce-library-contract`](../gov-enforce-library-contract/SKILL.md)
- When validating a single cross-cutting concern — use
  [`gov-enforce-caching-rules`](../gov-enforce-caching-rules/SKILL.md) or
  [`gov-enforce-error-handling`](../gov-enforce-error-handling/SKILL.md) instead

## Responsibilities

- Evaluate all 80 contract rules across the 7 layers
- Mark every check PASS, VIOLATION or N/A (the layer does not exist in the change)
- Reject non-compliant code with specific rule references

## Constraints

- MUST NOT generate or modify application code
- MUST NOT fix violations automatically — report them
- MUST NOT skip any check — all 80 rules are evaluated; a check that cannot apply is `N/A`,
  never `PASS`

## Output

- A compliance report with PASS/VIOLATION/N/A per check across all 7 layers, and rule IDs for
  every failure

## Enforcement Checklist

### LAYER 0: Domain (7 checks)

Applies to every rule the unit's DOMAIN RULES assign to `owner layer: domain`
(profile `domain_behaviour_placement: domain_classes`).

```
[ ] A.0.1 — A domain class exists for every entity with `owner layer: domain` rules
             (invariants, allowed state transitions, guard conditions)
[ ] A.0.2 — The domain class carries NO Spring, JPA or Spring AI annotations
[ ] A.0.3 — The domain class never reaches a repository, a port, the model or the network —
             all data is passed in as plain arguments
[ ] A.0.4 — Every rule violation throws the module's domain exception with its error-catalog code
[ ] A.0.5 — The domain class is constructed ONLY via static factories create(...) / from(...)
[ ] A.0.6 — The domain class never imports another module — cross-module facts are resolved by
             the service through the published contract interface and passed in
[ ] A.0.7 — At most one domain class per concept; a shared policy class exists only when a rule
             genuinely spans several entities. Flag "one policy class per entity" as over-application
```

### LAYER 1: Entity (15 checks)

```
[ ] A.1.1  — No base class, no audit superclass, no soft-delete flag, no activate()/deactivate()
[ ] A.1.2  — Table and column names match the db-script (its `dbf-matrix` block / `sql` fence) verbatim
[ ] A.1.3  — PK is Long {entity}Id with GenerationType.IDENTITY (NUMBER(19) GENERATED BY DEFAULT AS IDENTITY)
[ ] A.1.4  — Java types follow the oracle19c mapping of the module's CORE unit (R1)
[ ] A.1.5  — `nullable` matches the db-script's NOT NULL exactly
[ ] A.1.6  — NUMBER(1) maps to Boolean (NumericBooleanConverter only if the dialect needs it)
[ ] A.1.7  — Closed enums store exactly the db-script's CHECK constraint values
[ ] A.1.8  — Service codes and document types are String, never enums
[ ] A.1.9  — Host identifiers (request number, employee identity) are String columns, never FKs
[ ] A.1.10 — No association to another module's entity or to host data
[ ] A.1.11 — Every association used is fetch = FetchType.LAZY
[ ] A.1.12 — @UniqueConstraint / @Index declared inside @Table with names verbatim from the DDL
[ ] A.1.13 — Transactional entities map createdAt / updatedAt, never set from request data
[ ] A.1.14 — State columns change only through intention-revealing entity methods
[ ] A.1.15 — No createdBy / updatedBy / tenant column the db-script does not declare
```

### LAYER 2: Repository (9 checks)

```
[ ] A.2.1 — Extends JpaRepository for the module's own entity only
[ ] A.2.2 — Every query method maps to a QR-* repository operation of the unit (no speculative methods)
[ ] A.2.3 — Never injected outside its own module
[ ] A.2.4 — Existence checks use existsBy<Field>() rather than loading the row
[ ] A.2.5 — Reads that the unit marks READ_ONLY run in a read-only transaction
[ ] A.2.6 — Rows loaded together use JOIN FETCH or an entity graph, never a lazy loop
[ ] A.2.7 — Counts use count queries, not collection.size()
[ ] A.2.8 — Native SQL (e.g. a LOCK TABLE the unit prescribes) uses bound parameters only
[ ] A.2.9 — No dead code — every method has a caller
```

### LAYER 3: DTO (10 checks)

```
[ ] A.3.1  — Request/response DTOs are Java records (or immutable classes) matching the API
             document's schemas field for field — names, types, required
[ ] A.3.2  — Validation annotations reproduce the API document's constraints
             (required, maxLength, pattern, enum) — no stricter, no looser
[ ] A.3.3  — Request DTOs exclude the PK, audit fields and every system-set field
[ ] A.3.4  — Responses carry exactly the documented fields — never the PK unless documented,
             never SQL text, connection settings or credentials
[ ] A.3.5  — Responses are plain objects / arrays: no envelope, no paging wrapper unless the
             API document declares one
[ ] A.3.6  — Timestamps serialise as the API document states (OffsetDateTime, ISO-8601)
[ ] A.3.7  — Value objects crossing a module boundary are immutable (records with unmodifiable lists)
[ ] A.3.8  — Mapping entity ↔ DTO lives in one place per resource (a mapper or the record's factory),
             handles null input, and holds no decision logic
[ ] A.3.9  — No DTO carries request data a module's plan forbids it to hold
[ ] A.3.10 — Every DTO field is documented (springdoc @Schema or the project's chosen equivalent)
```

### LAYER 4: Port / Adapter (10 checks)

Every external dependency — the host query channel (MCP / read-only JDBC), the document source
and readers, the model — is a port with a replaceable adapter.

```
[ ] A.4.1  — The port is a plain Java interface in the module, named for what it does, with no
             adapter type in its signature
[ ] A.4.2  — The adapter implements the port and is the ONLY class touching the external API
             (MCP client, JDBC DataSource of the host, file system, Spring AI)
[ ] A.4.3  — The query adapter runs only the queries written in the service definition, with
             bound parameters, through a read-only connection — never SQL built from free text
[ ] A.4.4  — The document adapter validates every path inside the configured storage root
             before opening it
[ ] A.4.5  — The model adapter uses only ChatModel / Prompt / ChatOptions (and BeanOutputConverter
             for structured output) — no provider-specific option class or feature
[ ] A.4.6  — The model adapter registers no tool that runs SQL, reads files or calls the Approval API
[ ] A.4.7  — Document content reaches the model only as delimited data, never as instructions
[ ] A.4.8  — Every adapter applies the per-check limits it owns (aias.check.timeout, max-rows,
             max-file-size, max-uploads) and translates their breach into the documented outcome
[ ] A.4.9  — Every adapter translates its external exceptions into the module's own error type,
             keeping the cause — nothing external escapes the port
[ ] A.4.10 — An unreadable or missing item is returned as a recorded outcome, never dropped
```

### LAYER 5: Service (17 checks)

```
[ ] A.5.1  — @Service, constructor injection only, dependencies final
[ ] A.5.2  — NO authorization annotation, no permission check — caller authentication is
             deferred (amendment A2); its presence is a violation, not a precaution
[ ] A.5.3  — @Transactional on every write
[ ] A.5.4  — @Transactional(readOnly = true) on every read
[ ] A.5.5  — No model, MCP or host call while a database transaction is held open, unless the
             unit prescribes it
[ ] A.5.6  — The method body is orchestration only: load → delegate decision → act → return
[ ] A.5.7  — Rules with `owner layer: domain` are delegated to the domain class, never inlined
             (automatic rejection trigger)
[ ] A.5.8  — Rules with `owner layer: service` are implemented here, in the order the unit lists them
[ ] A.5.9  — Returns DTOs / value objects — never an entity across the controller or a module boundary
[ ] A.5.10 — Other modules are reached only through their published contract interface (injected,
             in-process) — never their repository, entity or internal service
[ ] A.5.11 — The Approval API is invoked only from the employee-decision operation, and only
             where the service version enables it
[ ] A.5.12 — No state is kept between checks: no static field, cache or session holds a query
             result, document content or model output
[ ] A.5.13 — Error codes come from the module's constants matching the error-catalog block
[ ] A.5.14 — Every runtime failure is the module's error type (see gov-enforce-error-handling)
[ ] A.5.15 — log.info for state changes, log.debug for reads; no document content, query
             results, prompts or completions at info level or above
[ ] A.5.16 — Any caller-supplied filter is validated against the documented parameters only
[ ] A.5.17 — Asynchronous work (a check accepted with 202) runs off the request thread and its
             outcome is recorded — never lost when the request returns
```

### LAYER 6: Controller (12 checks)

```
[ ] A.6.1  — @RestController with @RequestMapping under /api/v1/{resource}; constructor injection
[ ] A.6.2  — Injects ONLY services
[ ] A.6.3  — Every endpoint matches an operation of the API document (method, path, parameters,
             status) — no undocumented endpoint
[ ] A.6.4  — Only POST (create) and GET (read) — no PUT, PATCH or DELETE
[ ] A.6.5  — Success status is the documented one (201 create, 202 accepted check, 200 read)
[ ] A.6.6  — Errors are produced by the module's single @RestControllerAdvice as ProblemDetail —
             never built in the controller
[ ] A.6.7  — @Valid on every @RequestBody; multipart limits as the unit states
[ ] A.6.8  — No authorization annotation, no security filter (amendment A2)
[ ] A.6.9  — Path variables declare their name explicitly (@PathVariable("checkId"))
[ ] A.6.10 — @Operation (or the chosen equivalent) on every method, carrying the API id
[ ] A.6.11 — Responses are plain JSON — no envelope, no server-rendered page
[ ] A.6.12 — ZERO business logic
```

## Status → HTTP Mapping

The HTTP status of every error is part of its code — `{MOD}-{http}[-{SLUG}]` — and is fixed by
the module's `error-catalog` block, not chosen in code. Success statuses come from the API
document. The aias status set:

| Situation | HTTP |
|-----------|------|
| Read succeeded | 200 |
| Created (upload, decision) | 201 |
| Check accepted, running asynchronously | 202 |
| Request cannot be read / structurally invalid | 400 |
| Not found | 404 |
| Conflict with the current state (not awaiting documents, already decided) | 409 |
| Upload too large | 413 |
| Unsupported media type | 415 |
| Rule refusal not tied to a missing item (service not available, wrong fetch mode) | 422 |
| Unexpected failure | 500 |
| Host Approval API failed / timed out | 502 / 504 |
| 401 / 403 | in the profile's set but unused until caller authentication arrives (amendment A2) |

## Automatic Rejection Triggers

These patterns trigger IMMEDIATE rejection — no exceptions:

| Pattern | Reason |
|---------|--------|
| A raw `RuntimeException` thrown for a runtime failure | Must use the module's error type with a catalog code |
| An authorization annotation, permission check or security filter | Caller authentication is deferred (amendment A2) |
| An error response not built as ProblemDetail with a `code` | Error contract broken |
| A response envelope or a server-rendered page | aias responses are plain JSON |
| A PUT, PATCH or DELETE endpoint | aias exposes POST create / GET read only |
| `GenerationType.SEQUENCE` / `AUTO` | aias PKs are identity columns |
| A soft-delete or active flag, or `activate()`/`deactivate()` | Hard delete only |
| A repository injected outside its module, or another module's entity / repository / internal service used | Module boundary — use the published contract interface |
| A host identifier mapped as a foreign key or association | Host data lives outside this schema |
| SQL built from free text, or a query not written in the service definition | Guardrail G4 |
| A file opened before its path is validated inside the storage root | Guardrail G5 |
| A model tool that runs SQL, reads files or calls the Approval API | Guardrails G1, G2 |
| A provider-specific Spring AI class in the engine | Guardrail G12 / AIAS-9 |
| A controller containing business logic, or injecting a repository or a port | Thin-controller / layer violation |
| A `domain`-owned rule inlined in a service method | Must delegate to the domain class (A.5.7) |
| A domain class annotated with `@Component`/`@Service`/`@Entity`, or holding a repository / port | Must be a plain class (A.0.2, A.0.3) |

## Shared-Layer Consumption Checks (CU.1–CU.6)

| # | Check | Expected | Violation |
|---|-------|----------|-----------|
| CU.1 | One ProblemDetail advice per module boundary the plan names (e.g. INT's `IntegrationProblemAdvice`) | the advice the CORE unit created | a second, per-controller handler |
| CU.2 | Error codes from the module's constants class | constants matching the `error-catalog` block | inline code strings |
| CU.3 | Per-check limits read from `aias.check.*` configuration | the CORE unit's properties class | a hardcoded limit, or a limit read from a service definition |
| CU.4 | Other modules reached through their published contract interface | injected interface from `contract-<mod>.md` | a direct repository / entity / service import |
| CU.5 | External systems reached through the module's ports | port interface + adapter | an MCP / JDBC / file / Spring AI call outside an adapter |
| CU.6 | No duplicate configuration properties class for the same `aias.*` prefix | one class per prefix | a second class binding the same keys |

A unit failing any CU check is non-compliant regardless of its layer scores.
